# Day 10 纯向量与纯 BM25 检索对比

日期：2026-07-19（Asia/Shanghai）

本实验在同一组 PostgreSQL Chunk 与临时 Qdrant Point 上，比较纯 BGE 向量检索和纯
BM25 关键词检索。它不包含 RRF、Hybrid、Rerank 或 `/chat` 接入，也不直接比较两路
原始 score。

## 1. 实验环境与公平性

| 项目 | 值 |
|---|---|
| Chunk 配置 | `500/100`，按页切分，`o200k_base` |
| 语料 | Day 9 自撰 8 页企业制度手册 |
| 共享 Chunk 数 | 24 |
| 正样本问题 | 12：精确编号、语义改写、混合表达各 4 条 |
| 负样本问题 | 3 条知识库外英文问题 |
| Top K | 5 |
| 向量检索 | 固定 revision `BAAI/bge-small-zh-v1.5`，512/Cosine |
| BM25 | `rank-bm25==0.2.2`，`BM25Okapi` 默认 `k1=1.5`、`b=0.75`、`epsilon=0.25` |

实验先把 24 个 Chunk 写入真实 PostgreSQL，再用完全相同的 `chunk_id`、正文、页码、
文件名和 metadata 写入一次性 Qdrant collection。BM25 只读取这 24 个 PostgreSQL
Chunk；向量侧只查询对应临时 collection。测试结束后 PostgreSQL Document/Chunk 和
Qdrant collection 均在 `finally` 中删除。

命中判据沿用 Day 9：只做 NFKC + 首尾 strip，返回 Chunk 包含预先固定的
`expected_phrase` 才算命中。Hit@1、Hit@5、MRR@5 只比较排名，不比较 Cosine 与 BM25
原始分数。

## 2. BM25 分词与检索规则

- 文本统一 NFKC + `casefold()`；
- 中文连续段生成 unigram + bigram；
- 英文和数字按词保留；
- `VPN-6203`、`ERR_AUTH_42` 同时保留完整复合标识和拆分组成部分；
- query token 有序去重，corpus token 保留重复词频；
- 使用 `get_scores()`，不使用会补齐无关结果的 `get_top_n()`；
- 是否返回结果只看 query/document token 是否有交集，不使用 `score > 0`；
- `doc_id` 在 Top-K 前过滤；并列按 doc_id、chunk_index、chunk_id 稳定排序。

BM25 score 不是概率，可能大于 1、等于 0 或为负，并会随 corpus 改变；不能套用 Day 8
的 `0.46` 门槛，也不能与 Cosine score 直接比较。

## 5. 观察与适用场景

- BM25 在精确编号/关键词组表现最稳定：`6203` 从向量第 4 提升到 BM25 第 1，精确类
  四题全部 Top 1。
- 当前语义改写子集中，两路都只有 0.500 Hit@1；BM25 的中文 unigram/bigram 仍能利用
  局部字词重合把四题全部召回 Top 5，但这不等于 BM25 能理解同义语义。
- 混合表达同时包含关键词和自然描述，两路在本语料上都满分。
- 纯向量即使面对知识库外问题也会返回最近邻；纯 BM25 的 token-overlap 门控能对完全
  无词项交集的问题返回空数组。
- 这组结果说明两路错误形态不同，为 Day 11 研究 RRF 提供动机，但 Day 10 不实现融合。

## 6. 局限性

1. 语料仍是受控、自撰的 8 页制度手册，只有 24 个 Chunk 和 12 个正样本问题。
2. 中文 unigram/bigram 会产生大量宽泛单字重合；它不是中文语义分词，也没有停用词、
   同义词或领域词典。
3. “语义改写”问题仍可能保留局部字面重合，因此不能据此宣称 BM25 具备语义理解能力。
4. 向量负样本返回最近邻是检索层预期行为；Day 8 仍由独立 `0.46` 生成门控处理，BM25
   未接入 `/chat`。
5. 指标只适用于当前模型、语料、切分和问题集，不证明 BM25 普遍优于向量，也不构成
   Hybrid/RRF 收益证据。
